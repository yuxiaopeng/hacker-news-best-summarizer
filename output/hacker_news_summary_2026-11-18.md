## 10. Optimizely compromised, served malware on Zoom, GitLab

**原文标题**: Optimizely compromised, served malware on Zoom, GitLab

**原文链接**: [https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)

On November 16, 2026, Optimizely's Web experimentation platform was compromised, delivering malicious JavaScript to visitors of 178 organizations, including major sites like Zoom, BBC, CNN, GitLab, and Salesforce.

Attackers gained unauthorized write access to customer "Project JavaScript" within Optimizely projects. This malicious code was then served from Optimizely's trusted CDN, appearing legitimate. Even Optimizely's own sites were affected.

The sophisticated malware, `track.js`, performed multiple functions:
1.  **Cryptocurrency address swapping:** It replaced legitimate BTC, ETH, TRON, Solana, etc., wallet addresses with the attacker's, both on-page and in the clipboard.
2.  **Payment card skimming:** It watched form submissions for card numbers, expiry dates, and CVVs, sending them to the attacker.
3.  **Cookie and screenshot theft:** It stole HTTPOnly-not-marked cookies and page screenshots, often when wallet/payment terms were present.
4.  **iOS exploit kits:** On iPhones and iPads, it loaded Coruna and DarkSword exploit kits for iOS versions 18.6 and earlier.

Approximately $7,040 in cryptocurrency was stolen within nine hours on November 16. The extent of card and cookie theft is unknown.

The incident highlights that trusted third-party JavaScript can be compromised without a site's own infrastructure being breached. Platforms like Report URI are designed to detect such unexpected script changes, and an appropriate Content Security Policy (CSP) could have blocked critical parts of the attack. Most of the malicious code was removed by 21:52 UTC on the same day.

This unchecked complexity and de-skilling threaten "organizational cognition"—the collective ability of companies to think and respond coherently. The author warns that society has placed excessive trust in these increasingly fragile and illegible technical systems, rendering critical infrastructure (like flights and banking) highly vulnerable to widespread outages and pushing the internet towards a breaking point.

## 31. Rust changed me as a developer

**原文标题**: Rust changed me as a developer

**原文链接**: [https://blog.startifact.com/posts/how-rust-changed-me/](https://blog.startifact.com/posts/how-rust-changed-me/)

Martijn Faassen recounts how Rust, a programming language significantly different from his prior experience, profoundly reshaped his development mindset over six years. He highlights several key areas of growth.

Firstly, Rust's **sum types (enums)** were a revelation. Unlike product types (structs), enums model variants (e.g., a `Person` is either a `Human` or a `Cat`), with the compiler enforcing exhaustive handling. Faassen found this a more direct and often superior abstraction mechanism than object-oriented interfaces for many cases, offering static safety with less ceremony.

Secondly, Rust enhanced his understanding of **dispatch and performance**. It clarified the distinction between dynamic, conditional, and especially compile-time dispatch (via generics), revealing how static type information allows the compiler to optimize code by specializing operations for specific types, thus avoiding runtime overhead.

Third, Rust solidified **type-driven development**. He realized types, like tests or documentation, force developers to model their domain and design APIs more carefully, leading to robust code that embodies "parse, don't validate" principles and guides architectural decisions.

A major surprise was Rust's ability to achieve "magic" functionality—like serialization (serde) or CLI parsing (clap)—at **compile time using macros**. This contrasted with runtime reflection in dynamic languages and introduced him to a new class of framework patterns built on code generation.

Finally, Rust's stringent **ownership system**, while initially challenging, forced a re-evaluation of architecture. By preventing common issues like data mutation during concurrent reading or circular references, it encouraged separating mutation from data usage and led to less coupled code with clearer data flow, ultimately improving overall design despite the initial friction.

In essence, Rust's distinct paradigms pushed Faassen to a deeper understanding of fundamental programming concepts, leading to more robust, performant, and thoughtfully architected software.

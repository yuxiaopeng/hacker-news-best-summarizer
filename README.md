## 1. 所有人工智能生成的代码都应该开源

**原文标题**: All AI-generated code should be Open Source

**原文链接**: [https://jakub.jankiewicz.org/blog/ai-code-open-source/](https://jakub.jankiewicz.org/blog/ai-code-open-source/)

本文主张所有人工智能生成的代码都应开源，并提出了两个核心论点。

首先，文章强调AI模型在大量公开可用的开源代码以及Stack Overflow等平台的内容上进行训练，这些内容带有要求署名的知识共享许可。这些训练数据通常未经许可抓取，因此将源自这些开放知识的代码转化为专有、闭源软件的行为，感觉就像是“许可证洗钱”。

其次，作者认为纯粹由AI生成的代码不应享有著作权，因为它缺乏人类创作性。文章引用了美国“猴子自拍”争议和美国版权局的指导意见，指出非人类不能拥有著作权，这促使维基共享资源将AI生成的图像强制规定为公共领域内容。尽管承认全球版权法的差异，作者提议，为了确保公平并尊重促成AI发展的开放生态系统，开发者应明确将AI生成的代码以开源许可发布，或通过CC0许可将其贡献给公共领域。

文章总结道，在人类干预最少的情况下创建的代码——即开发者主要提供提示，而对输出结果没有进行大量审查或修改的代码——应毫无疑问地开源。

An IT outage affecting Microsoft 365 services, including Outlook, led to a chlorine accident at Phantasialand's Hotel Ling Bao in Brühl. Due to the disruption, the theme park failed to receive critical alarm emails from its automated pool maintenance system, which had detected a malfunction causing excessive chlorine to be pumped into the pool.

As a result, 15 hotel guests suffered injuries, predominantly respiratory irritations, after visiting the pool. Initially, four guests were hospitalized, with one person remaining for observation due to a moderate injury. Emergency services confirmed the significantly elevated chlorine levels, leading to the temporary closure and subsequent reopening of the pool after the water was replaced.

The incident prompted other hotel operators, like Max Wiesen of "Mauritius Hotel und Therme," to review their own safety protocols, highlighting the importance of robust monitoring. Cybersecurity architect Stephan Skrobisch emphasized that Microsoft was not to blame, arguing instead that Phantasialand should have implemented additional warning mechanisms, such as acoustic signals, for critical safety systems, rather than solely relying on email notifications.

## 8. Universal XSS in uBlock Origin from website-driven element picker

**原文标题**: Universal XSS in uBlock Origin from website-driven element picker

**原文链接**: [https://iter.ca/post/ubo-uxss/](https://iter.ca/post/ubo-uxss/)

A critical one-click universal XSS vulnerability was discovered in uBlock Origin (MV2 Firefox version), allowing a malicious website to inject arbitrary JavaScript into any other site. The issue, primarily identified by GPT-5.6 Sol, stemmed from the extension's element picker functionality.

The attack involved four key steps:
1.  **Leaking the Extension UUID:** A malicious website could hook `XMLHttpRequest.prototype.open` to intercept an internal XHR request made by a uBlock Origin filter (`no-fetch-if`). Triggering this filter (e.g., by `fetch('/adsbygoogle.js')`) would expose the extension's unique `moz-extension://<UUID>` path.
2.  **Embedding the Element Picker:** With the UUID, the attacker created an invisible iframe, setting its `src` to `moz-extension://${UUID}/web_accessible_resources/epicker-ui.html`.
3.  **Driving Filter Injection:** The attacker then used `postMessage` to communicate with the embedded picker iframe. By manipulating the `opt` field (normally for filter types like `$image`) with a newline, they could bypass restrictions and inject an arbitrary trusted scriptlet filter, such as `"image\ngoogle.com##+js(trusted-rpnt, script, ...)"`.
4.  **User Interaction:** The attacker would then position the invisible iframe to align with the element picker's "Create" button, tricking the user into clicking it and thereby confirming the malicious filter.

Since filters added by the element picker are treated as trusted, the injected scriptlet could execute arbitrary JavaScript on any target website. The vulnerability has since been fixed, notably by requiring a secret password for communication with the element picker iframe.

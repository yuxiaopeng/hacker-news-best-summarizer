## 8. Tailcat – 类似于 netcat，但通过 Tailscale 的数据平面

**原文标题**: Tailcat – Like netcat, but over Tailscale’s data plane

**原文链接**: [https://github.com/tailscale/tailcat](https://github.com/tailscale/tailcat)

Tailcat是一个开源工具，类似于`netcat`，它可以通过Tailscale的WireGuard加密数据平面促进安全的点对点连接，关键在于，它*不*依赖于Tailscale的控制平面，也*不*需要Tailscale账户。它完全在用户空间运行，无需root权限、内核模块，也无需修改系统路由/DNS。

Tailcat服务器会生成一个短连接令牌（ConnBlob），其中包含其WireGuard公钥和DERP中继信息，然后通过带外方式与客户端共享。连接最初通过DERP中继（可以是Tailscale的公共中继，也可以是用户自托管的）进行引导，然后尝试通过magicsock进行NAT穿越，以建立直接的点对点UDP连接。

功能包括在机器间传输stdin/stdout、暴露本地TCP端口、托管无认证SSH服务器、充当SOCKS5代理以及用作出口节点。密钥管理支持用于一次性会话的临时密钥，或用于持久地址的已保存密钥，后者可以通过DNS TXT记录发布。它还提供使用WireGuard公钥进行客户端认证，并支持自定义DERP中继。

Tailcat利用了Tailscale现有的开源组件：用户空间WireGuard实现、用于NAT穿越和中继的magicsock，以及gVisor的Netstack作为其用户空间TCP/IP堆栈。它以CLI工具、Go库以及实验性的浏览器内Web演示的形式提供。

## 9. Saving 100 terabytes of memory by optimizing 1.1.1.1's DNS cache

**原文标题**: Saving 100 terabytes of memory by optimizing 1.1.1.1's DNS cache

**原文链接**: [https://blog.cloudflare.com/dns-cache-memory-optimization-1111/](https://blog.cloudflare.com/dns-cache-memory-optimization-1111/)

Cloudflare's Big Pineapple platform, powering 1.1.1.1 and other DNS services, optimized its massive DNS cache (250 billion entries) to save 100 terabytes of memory. A series of five memory storage changes reduced the per-entry footprint by 56% (from 953 to 420 bytes), simultaneously increasing cache insert throughput by 43% and dropping lookup latency by 19%.

Key optimizations included:
1.  **Capacity Field Elimination:** Replacing Rust's `Vec<T>` and `String` with `Box<[T]>` and `Box<str>` removed unnecessary capacity fields and over-allocated heap space, saving 64 bytes per entry.
2.  **Consolidated Record Lists:** Merging the answer, authority, and additional record sections into a single list with 2-byte offsets instead of separate 8-byte pointers and lengths saved 28 bytes per entry.
3.  **Optional Record Owners:** Storing the `Record` owner as an `Option<Box<Name>>` allowed it to be omitted when identical to the queried domain (the most common case), reducing heap allocations.
4.  **Boxing Large Enum Variants:** For the `RecordData` enum, common, small variants (like A and AAAA) were stored inline, while larger ones were boxed to the heap, minimizing padding waste.
5.  **Wire Format Storage:** The most significant change involved storing record data as raw bytes (`Box<[u8]>`) with length prefixes. This eliminated enum overhead, improved CPU cache locality, and expedited response construction by allowing direct byte copying for most record types.

Production rollout confirmed a 43% reduction in p99 resident memory per instance. Cloudflare plans to reinvest the freed memory into increasing cache capacity for better hit rates.

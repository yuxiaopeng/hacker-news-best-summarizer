Mark L. Egan的研究揭示，信用卡奖励构成了每年92亿美元的财富转移，主要从低收入家庭流向富裕的信用卡用户。出现这种情况是因为商家将信用卡交易费嵌入到所有购物者的商品价格中。尽管现金和借记卡用户支付了这些更高的价格，但只有信用卡用户获得了奖励，实际上是补贴了这些福利。例如，与高级信用卡用户相比，现金支付者面临相当于高出26%的销售税。

该系统演变的一个关键因素是《2010年多德-弗兰克法案》中的《德宾修正案》，该修正案对大型银行的借记卡交易费设定了上限。尽管旨在保护消费者，但它却意外地产生了累退效应。随着银行弥补收入损失，借记卡用户失去了奖励和免费支票等福利，而信用卡用户则在奖励不受影响的情况下，从整体更低的价格中获益。结果，中等收入的借记卡用户受损最大，而富裕的信用卡用户则从中获利。

消费者根据购物地点进行分类以及大型零售商协商更低的费用等缓解因素，在一定程度上减少了这种转移。然而，这一趋势预示着高级信用卡的使用将增加。政策制定者在权衡未来的改革时，必须考虑这些复杂的动态，以避免类似的意外累退结果。

## 7. 提示框需要延迟，之后需跳过此延迟。

**原文标题**: Tooltips need a delay, and then they need to skip it

**原文链接**: [https://blog.master.dev/tooltips-need-a-delay-and-then-they-need-to-skip-it/](https://blog.master.dev/tooltips-need-a-delay-and-then-they-need-to-skip-it/)

这篇文章探讨了一个常见的工具提示用户体验问题：如何防止它们在光标扫过时意外出现，同时确保相邻工具提示之间的平滑过渡。最初，设置0毫秒延迟会导致工具提示即时且具有侵扰性。固定的200毫秒延迟解决了这个问题，但在多个紧密排列的标志之间移动时会造成迟钝的体验，因为每个标志都需等待完整的延迟。

提出的解决方案引入了一个三段式交互模式：
1.  **初始延迟：** 工具提示在首次悬停时等待200毫秒后打开。
2.  **暖窗期：** 工具提示关闭后，开始300毫秒的“暖窗期”计时器。如果用户在此300毫秒内悬停在另一个元素上，新的工具提示会立即打开，跳过延迟和动画。
3.  **冷却期：** 一旦300毫秒计时器在没有进一步交互的情况下到期，页面进入“冷却”状态，后续悬停将重新启用200毫秒延迟。

React实现使用`TooltipProvider`来管理共享的`isWarm`状态（使用`useRef`以避免重新渲染）。在`onMouseEnter`时，如果`isWarm`为真，工具提示立即显示，并应用`data-instant="true"`属性，供CSS移除`transition-duration`。否则，使用200毫秒的`setTimeout`。在`onMouseLeave`时，任何待处理的打开计时器都会被清除，工具提示关闭，并且提供者启动300毫秒的冷却期。`markOpened`函数取消任何正在进行的冷却，从而在元素之间移动时有效保持“暖”状态。

作者解释了这些时间设置：200毫秒的打开延迟平衡了意外触发和响应速度；300毫秒的暖窗期允许相邻元素之间平滑过渡，同时又不会过长；0毫秒的关闭延迟确保了清晰的反馈。文章最后强调，尽管AI可以构建功能性组件，但人类的判断力和品味对于提供精致的用户体验至关重要。
